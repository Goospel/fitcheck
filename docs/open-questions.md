# 팀 확인 필요 — 열린 결정 목록

확정되지 않은 값·규칙을 한 곳에 모은다. **여기 있는 것을 추측으로 채우면 안 된다** ([CLAUDE.md 1절](../CLAUDE.md)).

세 종류를 구분한다. 섞으면 "다 급한 것"처럼 보여서 아무것도 안 정해진다.

| | 뜻 |
|---|---|
| 🔴 **막힘** | 답이 없으면 그 작업이 못 나간다 |
| 🟡 **임시 진행** | 잠정값으로 굴러가는 중. 틀려도 되돌릴 수 있지만 늦을수록 비싸다 |
| 🟢 **운영** | 코드가 아니라 계정·권한 문제 |

**답이 확정되면** 🔴🟡 항목은 [CLAUDE.md 1절](../CLAUDE.md)(확정 상수) 또는 `docs/contracts.md`로 옮기고 여기엔 ✅ 와 결론만 남긴다. 이 문서가 사실의 출처가 되면 안 된다.

## 🔴 막힘

### Q1 · 기장 5단계를 무엇으로 판정하는가

**막는 것** A3 (BE-1) — 오늘 오후 · **승인 등급** 3명 동의 (확정 상수)

CLAUDE.md 1절에 **문구 5종은 확정돼 있는데 판정 기준이 없다.**

```
허리선 위 / 허리선 / 골반 / 엉덩이 중간 / 엉덩이 아래
```

B3에서 의류 **총장**(cm)을 필수로 받고, A3는 "키 → 상체 기준점 추정"을 하기로 돼 있다. 그런데 **키 175cm인 사람에게 총장 68cm가 골반인지 엉덩이 중간인지**를 정하는 값이 어디에도 없다. 경계가 4개 필요하다.

**필요한 답** — 키 대비 비율이든 절대 cm든, 어깨점에서 각 랜드마크까지의 거리 4개

**고를 수 있는 길**

1. PRD·화면 설계서에 이미 있으면 그대로 옮긴다 ← **먼저 확인할 것**
2. 없으면 팀이 근거 자료 한 장(인체 치수 표 등)을 정해서 확정한다
3. 둘 다 안 되면 **A3에서 기장을 빼고** 리포트에 총장 숫자만 표시한다

> ⚠️ 3번은 D3(프롬프트 변환)의 "밑단이 엉덩이를 반쯤 덮게" 지시가 같이 죽는다는 뜻이다. 생성 이미지 품질이 떨어진다. 마지막 수단이다.

### Q2 · 소매 3단계를 무엇으로 판정하는가

**막는 것** A3 (BE-1) — 오늘 오후 · **승인 등급** 3명 동의 (확정 상수)

Q1과 같은 문제인데 훨씬 작다. 계산식은 이미 있다.

```
소매 길이 차 = 의류 소매길이 − 사용자 팔길이     ← CLAUDE.md 1절, 확정
손목 위 / 손목 / 손등 일부 덮음                  ← 문구도 확정
```

**모르는 것은 경계 2개뿐이다.** 몇 cm부터 "손목"이고 몇 cm부터 "손등 일부 덮음"인가.

**필요한 답** — 숫자 2개. 예: `−3cm 미만 = 손목 위 / −3 ~ +2 = 손목 / +2 초과 = 손등 일부 덮음` (숫자는 **예시일 뿐 확정 아님**)

### Q3 · A4 신체 치수 추정 계수의 근거

**막는 것** A4 (BE-1) — 오늘 오후 · **승인 등급** 3명 동의 (확정 상수)

키·몸무게·성별 → 어깨너비·가슴둘레·허리둘레·팔길이를 추정해야 한다. plan.md에 "성별별 근사 회귀식 하나를 쓰고 계수는 상수로 뺀다"까지는 적혀 있지만, **그 계수 자체를 지어낼 수 없다.**

PRD는 "사이즈코리아 통계"라고 썼는데 3일 안에 그 데이터를 받아 정제할 수 없다.

**필요한 답** — 계수의 출처 하나. 정밀할 필요 없다. **근거가 있는 표 한 장이면 된다.**

**고를 수 있는 길**

1. 사이즈코리아 요약 표나 공개된 인체 치수 표를 누구든 한 장 찾아온다 (30분)
2. 못 찾으면 **추정을 아예 빼고**, 프로필에서 실측 4개 입력을 강하게 유도한다
   - 이 경우 프로필 정확도 `n/5` 와 "추정" 배지의 의미가 바뀐다 → 화면 설계서 원칙 4와 충돌하는지 확인 필요

> 2번은 시연 흐름을 바꾼다. "키·몸무게만 넣어도 바로 결과가 나온다"가 이 서비스의 진입 장벽 낮추는 지점이었다.

### Q4 · 어깨·허리·소매도 등급 문구가 있는가

**막는 것** A5 (BE-1) — 내일 오전 · **승인 등급** 3명 동의 (확정 상수)

가슴 여유는 5단계 등급이 확정돼 있다. 그런데 plan.md의 D3 매핑표에 이런 줄이 있다.

```
어깨 +4cm → 드롭숄더
```

**+4cm가 임계값인지 예시인지 모른다.** 어깨·허리·소매도 각각 판정 문구를 갖는지, 아니면 숫자만 나오고 문구는 가슴에만 있는지가 A5 응답 모양(= 계약 2)을 바꾼다.

**필요한 답** — 화면 설계서에서 핏 리포트 화면을 보고, 부위별로 문구가 붙는지 확인

### Q5 · 이미지 생성 모델 + 결제 수단

**막는 것** D0 → D4 전체 (BE-3) — 오늘 오전 · **승인 등급** 담당자 결정 후 공유

plan.md R1. 모델을 안 정하면 D3 프롬프트 형식도 못 정한다.

**필요한 답 두 개**

1. 어느 모델 — 실제로 이미지 1장 뽑아보고 정한다. 비교 실측할 시간 없다
2. **Replicate 카드 등록이 되는가** — 팀 예산이 없으면 무료 티어가 있는 범용 모델로 간다

## 🟡 임시 진행

되돌릴 수 있지만 **코드에 이미 들어가 있다.** 아니면 지금 말해야 싸다.

### T1 · 등급 문구 `타이트핏` · `슬림핏`

**들어간 곳** `fit/grade.py` · **승인 등급** 3명 동의

CLAUDE.md 1절 도식은 `타이트 / 슬림 / 레귤러 / 세미오버 / 오버` 로 줄여 썼는데, 산문과 6절 API 예시는 `레귤러핏` · `세미오버핏` · `오버핏` 로 **핏**이 붙어 있다. 명시가 없는 나머지 둘을 같은 패턴으로 맞췄다.

**되돌리는 비용** 2줄 + 테스트 문자열. 지금은 싸다. **프론트가 문자열로 분기하기 시작하면 비싸진다.**

문구 5종은 `fit.grade.THRESHOLDS` · `TIGHTEST` 에 있다. **D3는 문자열을 새로 쓰지 말고 여기서 import 할 것.**

### T2 · 신축성이 목록에 없는 값이면 「없음」 취급

**들어간 곳** `fit/grade.py` · **승인 등급** 3명 동의

CLAUDE.md는 `좋음 / 약간 / 없음 / 미입력` 네 가지만 규정한다. 오타 같은 5번째 경우가 안 정해져 있어서 「없음」으로 떨어뜨렸다.

보정을 안 주면 더 타이트하게 판정되고 → 사용자가 한 사이즈 올려 산다. "큰 옷을 사게 하는 편이 작은 옷보다 낫다"는 명시된 원칙과 같은 방향이다. 예외를 던지는 쪽은 시연 중 500이 난다.

### T3 · 에러 응답 모양

**들어간 곳** `core/errors.py` · **승인 등급** BE-2 (소유자)

```json
{ "error": { "code": "GARMENT_NOT_FOUND", "message": "의류를 찾을 수 없습니다" } }
```

부트스트랩으로 먼저 넣었다. `core/` 소유는 BE-2다. **모양을 바꾸려면 지금 바꿔야 한다** — 세 명의 API가 전부 이 모양으로 나가고 프론트가 `error.code` 로 분기한다.

### T4 · 마이그레이션 도구 없이 공용 DB 1개

**승인 등급** 3명 동의 (이미 PR #3에서 합의됨, 재확인용)

R3(스키마 지연)를 R4(공용 DB 사고)와 맞바꾼 결정이다. **BE-2가 컬럼을 잘못 지우면 셋이 같이 멈춘다.** 3일·3명이라 이쪽이 낫다고 봤다. 되돌리려면 Alembic 30분.

### T5 · Python 3.12 고정

**들어간 곳** `.python-version` · **승인 등급** 알림만

`uv` 가 3.14를 집고 있었다. 셋이 다른 인터프리터를 쓰면 `uv.lock` 이 있어도 갈라진다. 다음 `uv sync` 때 자동 전환되므로 따로 할 일은 없다.
